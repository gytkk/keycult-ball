좌표 원점은 볼 중심의 평면 위치와 키필드 중심 `(0,0)`, +x는 오른쪽, +y는 사용자 방향. 도면은 외장·일반 직사각형 참조 경계·키필드를 **임시로 동심 정렬**했다. 실물 플레이트 기준점과 다시 대조해야 한다. 공개 SVG/HTML/PNG/PDF에는 공식 윤곽 좌표나 오버레이를 넣지 않는다. 별도 로컬 윤곽 검사의 좌표 변환과 0.01mm 허용오차 샘플링 방법은 [출처 문서](sources/README.md)에 기록하며, 그 검사도 가공 원본을 대신하지 않는다.

### Keyball 원본 기구에서 확인한 내용

기준 커밋은 `Yowkees/keyball@e1d1948e6e60a83f6b3566a209326508200d64ce`. 조립 가이드 [B1]는 **34mm 볼**, 세라믹 지지구 3개, 홀더 상·하부 결합용 작은 머리 M1.7 나사 2개와 본체 아래에서 체결하는 flat-head M1.7 나사 2개를 설명한다.

**센서 PCB는 메인 PCB에 수직으로 서서 홀더 뒤쪽 포켓에 들어간다.** 7핀 L자 커넥터를 사용한다 [B1]. 따라서 센서를 볼 밑에 수평으로 쌓는 단면으로 높이를 추정하지 않았다. 추천 모듈의 뒤쪽은 도면에서 −y 방향으로 두는 것을 검토하되, 정확한 센서 위치는 미정이다.

Keyball46의 공개 `Trackball_PCB_gerber.zip` [B2] 내 `ball_sensor-Edge_Cuts.gbr`를 직접 읽어 **기판 외곽 22.000 × 25.000mm**를 확인했다. `%MOMM*%`와 4.6 좌표 형식에 따라 X=100…122, Y=−100…−75mm이며 U자 절개는 8.6 × 15.7mm. 이는 **2022년 Keyball46 센서 기판**의 2D 외곽이지 현재 판매되는 모든 리비전의 3D 조립 외피가 아니다. 기판 두께·부품·렌즈·커넥터 돌출은 미확정이다. 22×25mm를 평면도에 눕혀 놓지 않았다.

공개 저장소 조사 범위에서 독립 홀더 STEP/STL은 확보하지 못했다. Keyball39 공개 STL은 키보드 하우징 전체라 그 바운딩 박스를 홀더 크기로 사용하지 않았다. 해당 하우징에서 유도된 약 16mm 체결 피치도 실제 홀더 제조 치수·드릴 위치로 채택하지 않았다. **홀더 최대 폭/플랜지/높이, 볼 중심 Z, 나사 좌표, 광학 간격은 공급자 기구도 또는 실물 실측이 필요하다.** 원문은 아래 고정 커밋 출처에서 조회하며, 수치·한계는 [keyball-evidence.json](sources/keyball-evidence.json)에 기록했다.

## 2. 추천: 15u / 중앙 3u / 65키

### 평면 기하

- 전체 명목 키필드: **285.75 × 95.25mm = 15 × 5u**.
- 좌·우 각각 6열, 가운데 3열. 중앙은 홈행 및 바로 위·아래 행을 비워 **57.15 × 57.15mm** 확보.
- 맨 윗행 중앙에는 1u 세 키, 맨 아랫행 중앙에는 1.5u M1/M2 두 키가 있다. 키 수는 `15*5-3*3-1=65`.
- 행 중심 y: **−38.10, −19.05, 0, +19.05, +38.10mm**.
- 기본 열 중심 x는 -133.35부터 +133.35mm까지 19.05mm 간격이다. 중앙 3열의 중간 3행에는 스위치가 없다. 하단 중앙 M1/M2의 중심은 각각 (-14.2875,38.1), (14.2875,38.1)mm다.
- **G=(-38.10,0), H=(+38.10,0), 볼=(0,0)**. G–H 중심 간격 76.20mm. 2u 대안보다 19.05mm 넓다.
- 1u/1.5u 키캡 평면 가정의 전체 점유 외곽은 **284.70 × 94.20mm**.

```text
Esc   1    2    3    4    5   | Vol− Mute Vol+ |   6    7    8    9    0   Bksp
Tab   Q    W    E    R    T   |               |   Y    U    I    O    P     \
Caps  A    S    D    F    G   |     Ø34       |   H    J    K    L    ;   Enter
Shift Z    X    C    V    B   |               |   N    M    ,    .    /   Shift
Ctrl GUI  Alt  Fn  Space Del |   M1     M2   | Bksp Space Fn  Left Down Right
```

문자 키는 표준 QWERTY의 논리 순서를 유지하지만 stagger가 없어 타건 위치는 달라진다. 하단 M1/M2는 각각 왼쪽/오른쪽 마우스 버튼이며 1.5u이고, 나머지는 1u다. M3 물리 키는 제거하며 가운데 버튼 기능의 대체 배정은 아직 정하지 않았다. 1.5u 키캡 평면은 `18+(1.5-1)*19.05=27.525mm` 너비와 18mm 높이를 가정한다. 실제 키캡 하단, 스위치와 안정기 필요 여부는 실물로 확인해야 한다. 양쪽 Fn은 같은 순간 레이어로 시작한다. 예비 Fn층에는 숫자→F1–F10, Vol−/Mute→F11/F12, Q/W/E/R/T→` [ ] - =`, P→작은따옴표, Down→Up을 배정하면 기본 기호·방향·기능 키를 확보할 수 있다. 휠/드래그스크롤·CPI 조절도 레이어 기능 후보이며 아직 QMK keymap을 구현한 것은 아니다.

### 왜 3u인가

**볼 Ø34와 홀더 전체 외곽은 다르다.** 도면의 주황색 **50 × 50mm**는 홀더·센서·체결부를 검토하기 위한 *임시 예약 영역*이다. 실측 홀더 크기, 플레이트 절개 크기, PCB 절개 크기가 아니다. 최종 조립체가 이 영역을 벗어나면 배치 검토를 다시 해야 한다.

65키안은 1u 18 x 18mm와 1.5u 27.525 x 18mm 키캡 평면을 가정할 때, 가장 가까운 G/H 및 중앙 위·아래 키까지 볼 최대 투영 원의 여유가 **12.10mm**다. 50mm 사각형 예약 영역과 키캡 사이에는 **4.10mm**, 각 키캡을 명목 키 셀 전체로 보수적으로 잡아도 **3.575mm**가 남는다. 스위치 14mm 사각형과는 **6.10mm** 간격이다. 이것은 체결구·벽 두께·배선·제조 공차의 승인이 아니라, 해당 가정에서의 양의 평면 여유다.

### 별도 옵션: 상단 중앙 세 키 제거 / 15u / 62키

`layout.json`의 `rear_clearance`는 65키 기준안의 상단 중앙 Vol-/Mute/Vol+만 제거한다. 키 수는 `65-3=62`이며 하단 1.5u M1/M2와 나머지 키의 좌표·기능 표시는 그대로다. 명목 키필드 285.75 × 95.25mm, 볼 지름 34mm와 중심 `(0, 0)`, G/H x=±38.10mm도 유지한다.

중앙 빈 명목 영역은 3열 × 3행의 57.15 × 57.15mm에서 3열 × 4행의 57.15 × 76.20mm로 늘어난다. 좌표 범위는 x=-28.575..28.575mm, y=-47.625..28.575mm이며, 뒤쪽(-y)으로 한 행 19.05mm를 추가한다. 이는 키 셀을 비운 범위이며 실제 홀더 외곽, 보강판·PCB 절개 크기가 아니다. 중앙 50 × 50mm 임시 조립 예약 영역도 유지한다.

확보한 뒤쪽 공간에서 수직 센서 PCB와 배선을 배치하고, 재료를 남긴 지지 브리지나 넓은 체결 간격을 설계할 수 있는지 검토한다. 키 제거만으로 강성이나 장착 안정성이 개선됐다고 판단하지 않는다. 빈 직사각형 전체를 절개하면 강성이 낮아질 수 있으므로 실제 모듈 외곽, 체결 하중과 플레이트 휨을 확인해 필요한 개구와 지지 재료를 정한다. 볼과 센서를 같은 강체에 고정하는 조건은 유지한다. 볼을 키우거나 수직 공간을 늘린 설계가 아니며 실제 조립 가능 여부는 미확정이다.

65키 기준안의 Vol-/Mute 위치를 사용하는 예비 Fn층 제안은 이 옵션에 그대로 적용할 수 없다. 제거한 미디어 키와 F11/F12의 기능 배정은 후속 QMK keymap 설계에서 정하며, 현재는 펌웨어를 구현하지 않았다.

## 3. 너비 축소 비교안: 14u / 중앙 2u / 64키

중앙 두 열을 비우고 나머지는 같은 6열+6열 구조. 맨 위 중앙은 Vol−/Vol+, 맨 아래는 M1/M2로 줄인다. **볼만으로는 충돌하지 않지만 2u 안에 Keyball 조립체가 들어간다고 판단해서는 안 된다.**

| 비교 | 추천 15u·3u·65키 | 대안 14u·2u·64키 |
|---|---:|---:|
| 명목 키필드 W × H | 285.75 × 95.25 | 266.70 × 95.25 |
| 중앙 빈 명목 영역 | 57.15 × 57.15 | 38.10 × 57.15 |
| G/H x 좌표 | ±38.10 | ±28.575 |
| G–H 중심 거리 | 76.20 | 57.15 |
| 볼 Ø34→키캡 평면 가정 최소 | +12.10 | +2.575 |
| 볼 Ø34→14mm 스위치 비교 사각형 최소 | +14.10 | +4.575 |
| 임시 50mm 사각형→키캡 평면 가정 최소 | +4.10 | **−5.425 (겹침)** |
| 임시 50mm 사각형→명목 키 셀 최소 | +3.575 | **−5.950 (겹침)** |
| 임시 50mm 사각형→14mm 스위치 비교 사각형 최소 | +6.10 | **−3.425 (겹침)** |
| 외장 294.3mm와 명목 키필드의 좌우 차이/2 | 4.275 | 13.800 |
| 외장 111mm와 명목 키필드의 앞뒤 차이/2 | 7.875 | 7.875 |

마지막 두 행은 **외장 치수와의 산술 차이이지 실제 벽 두께나 내부 여유가 아니다.** 14u는 15u 프레임의 왼쪽에 붙이지 않고 동일한 원점을 중심으로 배치했다. 18mm 키캡 간 실제 중앙 통로 폭은 3u에서 58.20mm, 2u에서 39.15mm. 예를 들어 조립체와 키캡 사이 1mm씩을 남기려면 2u에서 조립체는 해당 높이에서 폭 **37.15mm 이하**여야 한다. 보수적인 셀 기준으로는 **36.10mm 이하**다. 볼 34mm와 벽·베어링·나사를 함께 수용하기 매우 제한적이다. 단, 특정 높이의 홀더가 키캡 아래로만 지나가면 3D 형상으로 별도 검증할 수 있으며 단순 2D 겹침만으로 영구 불가능이라 단정하지 않는다.

## 4. 공개 평면 검증과 별도 공식 윤곽 검사

### 현재 공개 검증

`build_artifacts.py`는 모든 키 중심, 키 수, 키캡–키캡/스위치–스위치 충돌, 볼 원–키 사각형 최소거리, 중앙 예약 사각형과의 부호 있는 간격을 계산한다. 이 평면 계산은 [validation.json](validation.json)에 저장한다. `uv run scripts/validate.py`의 별도 공개 플레이트 참조 검사 결과 `envelope-containment.json`은 **285.75 × 108.25mm 일반 직사각형 치수 경계**에 대한 포함·간격만 다룬다. 공식 탭이나 둥근 모서리 형상을 검사하지 않는다.

인접 키캡의 평면 가정 간 최소 간격은 **1.05mm**다. 추천안에서 키캡끼리·스위치 비교 사각형끼리의 겹침이 없고, 각 키의 비교 사각형은 볼 및 50mm 예약 영역과도 겹치지 않는다. 동일 키의 키캡과 스위치는 의도적으로 동심이며, 예약 영역은 볼을 포함한다. 볼–키캡 **12.10mm**, 예약 영역–키캡 **4.10mm**, 14u 대안의 예약 영역–키캡 **−5.425mm**는 윤곽 공개 방식과 무관하게 유지되는 배열 계산값이다.

### 과거 공식 윤곽 관측과 로컬 재현

[plate-containment.json](plate-containment.json)은 공식 DXF 바깥 폐곡선을 폴리곤으로 만들어 검사했던 **과거 수치 기록**이다. 공개 직사각형으로 다시 계산한 결과가 아니며, 윤곽 좌표를 포함하지 않는다.

이 과거 기록은 66키 기준안과 14u 64키 비교안만 다룬다. 현재 65키/62키 배열은 공개 평면 검사와 자체 1:1 인쇄 자료로 검토하며, 과거 공식 윤곽 기록을 새 옵션의 검증 결과로 보고하지 않는다. 당시 검사 결과는 다음과 같다.

- 추천 66키: 모든 14mm 스위치 비교 사각형이 공식 윤곽 안에 있었고, 윤곽까지 최소 **2.525mm**였다. 모든 18mm 키캡도 포함됐지만 둥근 모서리에서 최소 **약 0.327mm**로 작았다.
- 14u 대안도 포함됐으며 스위치 최소 2.525mm, 키캡 최소 0.525mm였다. 가로를 줄여도 5행의 앞뒤 위치가 같아 최소 여유는 크게 늘지 않았다.

이 관측을 재현하려면 원본 사용 조건을 확인하고 공식 DXF를 로컬 취득한 뒤 저장소 루트에서 `uv run scripts/verify_official_contour.py`를 실행한다. 이 별도 검사는 로컬 공식 DXF에서 윤곽을 다시 추출한다. 좌표 `sources/local/measured-official-dxf.json`과 재검사 출력은 Git에서 제외하며, 공개 생성·검증은 이 로컬 좌표에 의존하지 않는다. 취득·해시 확인 절차는 [재현 문서](../../docs/reproduction.md)를 따른다.

**직사각형 경계 포함 ≠ 정확한 플레이트 윤곽 포함 ≠ 케이스 개구부 통과**다. 과거 모서리 여유가 작으므로 실제 키캡 하단 치수, 개구부 코너 반경, 플레이트 평면 이동을 측정해야 한다. 18mm 가정이나 배열을 바꾸면 과거 결과는 그대로 적용할 수 없다. 핫스왑 소켓, 핀, 다이오드, 나사와 하부 부품은 이 14mm 사각형 검사에 포함되지 않았다. 어느 검사도 조립·제조 검증을 대신하지 않는다.

## 5. 볼 투영과 수직 단면

플레이트 윗면을 z=0, 볼 중심 높이를 c, 반지름을 R=17mm로 둔다.

- 볼 최상단: `c+17`, 최하단: `c−17`.
- 어떤 높이 z에서 볼 단면 직경: `2√(17²−(z−c)²)` (`|z−c|≤17`일 때만).
- 평면도에서는 높이와 무관한 최대 투영 Ø34를 사용했다. 볼 중심이 플레이트보다 높다고 해서 볼과 홀더의 실제 구멍을 Ø34로 정할 수는 없다.
- 예를 들어 **설명용으로만** c=8mm라면 볼 위끝 +25mm, 아래끝 −9mm. `section.svg`는 이 예를 표시하며, 실제 Keyball 조립 높이·배치 선택을 뜻하지 않는다.
- 홀더·베어링과 **홀더 뒤쪽에 서는 센서 PCB/렌즈**, L자 커넥터, 납땜·케이블 굴곡의 전체 외피를 검사해야 한다. 이 부품들이 모두 볼 바로 아래에 수평으로 놓인다고 가정하지 않는다. 센서와 볼 표면의 광학 거리는 원본 조립 구조대로 유지해야 한다.
- 필요한 바닥 여유는 `조립체의 플레이트 아래 최대 깊이 + 배선/절연/공차 + 최대 하향 휨`으로 검사한다. **20.35/35.8mm 외장 높이로 이 값을 대체하지 않는다.**

## 6. 홀더 고정 방식과 flex 영향

### 우선 검토: 볼+센서 모듈을 함께 새 플레이트에 고정

후속 로컬 기구 설계에서는 원본 외곽 탭과 케이스 접촉 형상을 유지하고, 중앙 모듈의 체결부·개구부를 새로 설계하는 방향을 검토한다. 공개 직사각형 참조 경계에는 이 체결 형상이 없다. **볼 홀더와 센서는 같은 강체 조립체**에 두어 키 입력이나 볼 조작 때 서로 움직이지 않게 한다. 1.5mm는 공식 기준 두께이지 새 재질의 강성을 보증하는 값이 아니다.

중앙 대형 절개는 플레이트 강성을 낮추고, 홀더·볼 질량과 손가락의 수평/수직 힘은 새 하중을 만든다. 기존 leaf spring과 합쳐지면 흔들림·광학 오차·바닥 접촉이 생길 수 있다. 초기 개인용 기구 시제품에서는 원본 사용 조건에 따라 로컬 공식 **NoLeaf 모델을 출발점으로 중앙 보강**을 검토할 수 있으며, 최종 판재·두께·리브는 체결 형상과 휨을 확인해 선택한다. 공개 SVG는 일반 직사각형 치수 경계만 표시하므로 공식 외곽 탭·Rev.1 정렬 핀·스프링을 재현한 도면이 아니다.

### 필요하면: 기존 케이스 체결점에 가역 브래킷

실물의 기존 나사 보스/체결점을 이용해 홀더와 센서를 케이스에 고정하면 볼 지지 강성 확보에 유리할 수 있다. **새 케이스 구멍·절삭을 전제로 하지 않는다.** 하지만 플레이트는 flex하고 볼은 고정되므로 둘 사이에 최대 상대 변위+공차 만큼 공간을 둬야 한다. 브래킷이 플레이트에 닿으면 flex를 막고 소음·힘 전달 경로가 바뀐다. 볼은 케이스, 센서는 플레이트에 따로 다는 방식은 상대 광학 위치가 바뀌므로 피한다. 사용 가능한 기존 체결점이 없다면 이 방식은 보류한다.

### 로컬 FreeCAD 보강판 초안

2026-10-30 macOS arm64의 FreeCAD 1.1.4에서 `scripts/build_plate.py`로 생성한 보강판 및 중앙 프레임 초안은 현재 65키와 62키 좌표를 사용한다. 공식 `Plate-NoLeaf.step`의 외곽선을 보존하고, 원본의 키/안정기 구멍 68개를 현재 직교 스위치 구멍으로 교체한다. 스위치 중심은 현재 KiCad 검사 보고서의 실제 stem 좌표와 대조하며 PCB 파일 해시가 달라지면 생성을 중단한다. 원본 NoLeaf가 보유 NovelKeys 케이스와 맞는지는 아직 확인되지 않았다.

| 항목 | 이번 초안의 값과 의미 |
| --- | --- |
| 보강판 | 공식 NoLeaf 외곽, 두께 1.5mm. 단일 솔리드 유지와 외곽 보존 검사 |
| 스위치 구멍 | 14 x 14mm 사각형 65개 또는 62개. MX 클립 형상, 코너와 가공 공차는 미확정 |
| 중앙 개구 | 지름 40mm의 설계 검토용 원. 실물 홀더 치수나 50mm 예약 영역에서 확정한 가공 치수가 아님 |
| 탈착식 프레임 | 48 x 48 x 3mm, 중앙 지름 40mm, 42mm 정사각 피치의 지름 2.2mm 구멍 4개. M2 체결을 검토하기 위한 자체 설계 가정 |
| 62키 프레임 | 뒤쪽 y=-40mm까지 폭 30mm의 재료를 남김. 센서 고정부를 추가할 바탕이며 센서 장착 구멍은 아직 없음 |
| 평면 여유 | 두 프레임 모두 1u 18 x 18mm, 1.5u 27.525 x 18mm 키캡 평면 가정과 최소 5.1mm 간격. 실제 키캡 하단이나 키 스트로크 검사 결과가 아님 |
| PCB와의 높이 | PCB 윗면 z=-5mm, 두께 1.6mm를 가정. 현재 PCB의 중앙은 뚫려 있지 않음 |

구조는 볼 홀더와 센서를 같은 탈착식 프레임에 장착하고, 이 프레임을 보강판의 네 점에 체결하는 방향이다. 현재 프레임은 실물 홀더의 대체품이 아니며 볼 지지점, 센서 광학 위치, 홀더 나사 패턴을 만들지 않았다. 62키안의 뒤쪽 재료는 수직 센서 지지부를 같은 프레임에 통합할 여지를 제공한다. 보강판과 PCB 사이의 가정상 간격은 3.5mm뿐이므로 나사 머리, 너트, 나사 끝과 절연 여유를 포함한 체결 스택을 검토해야 한다. 재질과 보강 리브, 휨은 아직 선정하거나 계산하지 않았다.

기존 설명용 볼 중심 z=8mm에서는 볼 최하단이 z=-9mm이고, 가정한 현재 PCB와 약 494.34mm3 겹친다. 모델에 이 간섭을 숨기지 않고 표시한다. 볼 중심을 z=13mm로 올린 비교 객체는 볼 자체가 PCB에서 1mm 떨어지지만 볼 상단이 보강판 위 30mm가 되며 홀더/센서 수납은 검증되지 않는다. 따라서 후속 설계는 실제 조립체에 맞는 PCB 개구 또는 허용 가능한 돌출 높이를 결정해야 한다. 모델의 `UnappliedPCBOpeningTool`은 비교용 도구이며 KiCad `Edge.Cuts`에 반영한 형상이 아니다.

편집용 FCStd, 보강판/프레임 STEP, 검토용 DXF와 이미지, 검사 JSON은 모두 `sources/local/plate-study/`에만 저장한다. 원본 형상을 포함하므로 공개 Git에 넣지 않는다. DXF의 곡선은 최대 편차 설정 0.01mm로 다각화한 검토용 자료이며 가공 발주에 사용하지 않는다. [재현 절차](../../docs/reproduction.md#freecad-보강판-초안)와 [출처 및 리비전 조사](sources/README.md)를 따른다.

## 7. 유선 QMK 전장 범위

### PCB 설계 출발점

2026-10-29 결정: **공개 GH60 KiCad 도면을 새 PCB 설계의 출발점으로 사용한다.** WT60-A의 정확한 PCB CAD 확보를 설계 시작의 선행 조건으로 두지 않는다. 기준 자료는 `komar007/gh60`의 커밋 `e7948cf44dbd3d43eb70296023a6fe3f471b44ba`에 있는 [keyboard.kicad_pcb](https://github.com/komar007/gh60/blob/e7948cf44dbd3d43eb70296023a6fe3f471b44ba/keyboard.kicad_pcb)와 [keyboard.sch](https://github.com/komar007/gh60/blob/e7948cf44dbd3d43eb70296023a6fe3f471b44ba/keyboard.sch)다. PCB 외곽과 기본 스위치 배치의 기준을 참고하되, 현재 프로젝트의 직교 배열과 중앙 포인팅 장치에 맞춰 스위치 좌표, 중앙 개구와 회로를 새로 설계한다.

호환 근거는 [Salvun의 WT60-D 제품 설명](https://salvun.com/products/wilba-60-pcb-wt60-d)이다. 이 PCB는 Poker2 규격의 USB 위치와 PCB 장착 홀을 사용하며, FAQ는 Keycult No.1/60에 장착하려면 PCB의 USB-C 커넥터를 제거하고 JST 커넥터를 납땜하면 된다고 명시한다. [Keycult 공식 FAQ](https://resources.keycult.com/faq_keycult_faq.html)도 No.1/60의 대체 PCB로 WT60-G를 명시한다. 이는 범용 60% PCB를 출발점으로 사용할 근거이며, 모든 GH60 파생 PCB나 위 GH60 파일 그대로의 실물 장착을 보증하는 내용은 아니다. WT60-D는 호환 근거이고, 위 GH60 파일은 설계 참고 원본이다.

No.1/60은 보강판이 케이스에 결합하고 PCB는 스위치를 통해 지지되는 구조이므로, 작은 PCB 외곽 치수 차이만으로 호환 불가라고 판단하지 않는다. 보강판의 케이스 결합 형상은 Keycult 자료를 기준으로 유지하고 GH60의 트레이 장착 홀은 그대로 재현할 필요가 없다. 새 메인 PCB에는 USB-C 포트를 두지 않고 외부 UDB C5-JSH를 연결한다. 제조 전에는 PCB 가장자리와 하부 부품의 케이스 간섭, 도터보드 장착과 커넥터 체결, 케이블 도통 및 삽입·굴곡 공간을 실물과 대조한다. 중앙 트랙볼의 높이와 개구, 지지 강성은 별도로 검증한다.

[65키 KiCad 초안](../pcb/README.md)은 GH60의 285.0×94.6mm 요약 외곽 치수만 참고하여 독립 작성했다. 공개 원본 CAD나 정확한 GH60/Keycult 윤곽을 포함하지 않는다. 출처·해시와 라이선스 근거의 한계는 [PCB 출처 기록](../pcb/sources.md)에 있다. 원본 파일의 취득과 파생 CAD 공개는 [자료 관리 기준](../../docs/alternatives-and-licenses.md)에 따라 해당 파일의 사용 조건을 확인하고 진행한다.

### 회로와 펌웨어

새 PCB는 직교 키 매트릭스+다이오드, QMK 지원 USB MCU, 센서 SPI 및 전원을 포함한다. 초안은 직접 실장 RP2040, 3.3V 로직, 5×15 매트릭스와 SPI0 예약 핀맵을 구현했다. DRAFT E는 2026-10-30 사용자 승인에 따라 UDB C5-JSH를 그대로 사용하는 가정으로 설계하며 외부 조립체 DB1을 회로도에만 표시한다. DB1의 메인 PCB footprint는 없고 기존 공통 부품 배치를 유지하고 하단 1.5u M1/M2 좌표에 맞춰 매트릭스를 다시 배선한다. J1 측 USB 데이터 배선은 F.Cu 중심으로 변경하고 접지 귀환 경로를 보완한다. JLC04161H-7628 후보 stackup 모델과 선폭·간격의 적용 범위는 [USB 배선 검토](../pcb/README.md#usb-routing-findings)를 따르며 제조사 승인이나 임피던스 검증 완료를 뜻하지 않는다. J1은 JST SM04B-SRSS-TB(LF)(SN), 1=VBUS_USB(외부 PTC 이후), 2=D-, 3=D+, 4=GND이며 적절한 길이의 번호 기준 1:1 케이블로 연결한다. 센서 모듈 전원·전압 변환은 미확정이며 [전기 범위](../pcb/README.md)를 따른다. 물리 5×15 배치는 논리 좌표이고 전기 매트릭스 배선은 별개다. 중앙에는 스위치/소켓뿐 아니라 PCB 부품·배선을 넣지 않는 영역과 필요 시 관통 개구부가 필요하다.

C5-JSH의 CC 5.1kΩ 저항 2개, TPD4E05U06 ESD 보호, ASMD1206-150 PTC, SMF6.0A TVS 및 실드의 GND 직결은 외부 보드가 담당한다. 메인 PCB의 F1 500mA와 USB 27Ω 직렬 저항은 유지한다. 실제 부하·돌입전류와 직렬 퓨즈의 전압 강하, 제조 stackup·케이블·접지 귀환 경로를 포함한 USB 신호 품질은 별도 검증 대상이다. [리비전별 회로 근거](../pcb/sources.md#usb-daughterboard-evidence)는 채택한 공개 C5-JSH를 설명하며, 보유 Keycult 순정 도터보드의 리비전·회로를 실측으로 확인한 기록은 아니다.

원본 Keyball46 센서 회로도 [B3]에는 커넥터 측 5V와 센서 측 1.9V, TPS73601 레귤레이터 및 TXS0102 레벨 변환기가 있고 7핀 신호는 SCLK/NCS/GND/5V/GND/MOSI/MISO이다. 핀 번호 방향은 해당 회로도와 실물 커넥터를 대조해야 한다. **PMW3360 생칩 5V 직결이나 임의 3.3V MCU의 무조건 호환으로 일반화하지 않는다.** 사용할 모듈 리비전과 MCU에 맞춰 로직·전원 인터페이스를 설계한다.

QMK 공식 문서에는 `POINTING_DEVICE_ENABLE = yes`, `POINTING_DEVICE_DRIVER = pmw3360`와 SPI/CS 설정이 명시되어 있다 [Q1]. 한 USB 연결에서 키보드와 포인팅 장치 보고를 처리하는 유선 설계 방향이다. **Keyball 완성 키보드 펌웨어를 그대로 새 PCB에 플래시한다는 뜻은 아니다.** 원본 Keyball39는 자체 드라이버를 쓰는 `POINTING_DEVICE_DRIVER = custom` 설정이며 [B4], 본가 PMW3360 설정과 동일한 구현이라고 단정하지 않는다. 매트릭스, MCU, CS, SPI, 센서 방향·CPI, 버튼·스크롤 처리를 새 보드로 포팅하고 검증한다.

C5-JSH의 채택은 승인된 설계 가정이므로 보유 순정 도터보드의 모델·보호회로 확인을 회로·PCB 설계의 선행 조건으로 두지 않는다. 케이블 길이는 조달로 해결하며 케이스 장착, 커넥터 체결·도통, 삽입·굴곡 공간과 하부 높이는 조립 전에 확인한다. 원본 리비전과 Rev.1의 부품을 혼용할 수 있다고 해석하지 않는다. 하부 높이가 부족할 때 소켓 대신 납땜을 검토할 수 있으나 먼저 실측한다.

## 8. 기존 도구 조사와 이번 산출물의 위치

새 CAD 시스템을 만들기 전에 유지되는 기존 도구를 확인했다(2026-10-29 GitHub API 확인):

- **Ergogen**: 2D 키 좌표와 외곽, 플레이트, 케이스, 미배선 PCB를 구성 파일로 생성한다 [T1]. 저장소 미보관 상태, 최근 push 2025-11-02. 키 좌표 중심의 다음 단계에 적합하지만 Keycult 공식 STEP의 장착 구조와 홀더 수직 충돌을 자동 해결하지 않는다.
- **FreeCAD**: STEP/DXF 등과 BRep·솔리드, 실단위 파라메트릭 설계, 어셈블리 지원 [T2]. 저장소 push 2026-10-29. 공식 STEP와 홀더 모델의 합본 조립·간섭 확인에 적합하다.
- **KiCad**: PCB 편집기로 DXF/SVG 가져오기와 DRC 및 3D 확인 기능이 있다 [T3]. 저장소 push 2026-10-29. 확정 외곽/부품 keepout을 이관하고 실제 회로·PCB를 설계할 단계에 사용한다.

권장 흐름은 **GH60와 기존 키 좌표를 참고한 KiCad 회로도/PCB 초안 작성, FreeCAD 기구 검토, 실측 반영 후 최종 배선과 제조 준비**다. 회로도와 PCB 초안은 실측을 기다리지 않고 진행하며, 단계별 산출물과 검증 기준은 [PCB 구현 계획](../../docs/pcb-implementation-plan.md)을 따른다. 기존 소형 Python 파일은 좌표 계산·검증·설명용 SVG/HTML을 반복 생성하는 도구이며 범용 CAD나 PCB 자동설계기가 아니다. 공식 파일의 로컬 측정에는 기존 ezdxf와 OpenCascade/CadQuery, 별도 공식 윤곽 포함 검사에는 Shapely를 사용했다. 공개 배치 생성은 정확한 공식 윤곽 파일을 요구하지 않는다.

## 9. 다음으로 필요한 최소 실측과 종이 검증

1. 케이스 정확한 리비전, 현재 플레이트/PCB/도터보드 모델과 방향·장착 사진을 확보한다.
2. 상부 **내부 개구부** 폭·깊이, 네 모서리 반경, 턱, 중심 오프셋을 플레이트 기준으로 측정한다. 실제 1u 키캡 하단을 포함해 각 끝 키가 통과하는지 확인한다.
3. 중앙 및 홀더 주변의 **플레이트 윗면→바닥/리브/나사/무게추 거리**를 여러 지점에서 측정한다. PCB와 소켓 밑 여유, 기존 케이블 통로도 포함한다.
4. 사용할 **정확한 Keyball 홀더 리비전·센서 PCB·커넥터**의 최대 XY 외곽과 z 스택, 체결 구멍 위치를 측정한다. 34mm 볼 자체만 재는 것으로 충분하지 않다.
5. 기준안의 `print-1to1.svg`와 62키 옵션의 `rear-clearance-print.svg`를 A3 가로, 100% 실제 크기로 인쇄한다. **100mm 기준선이 정확히 100mm인지 자로 확인**한다. A4 가로는 종이 폭 297mm라 294.3mm 외장과 프린터 여백을 담기 어렵다. A3 또는 타일 인쇄를 사용한다.
6. 분리한 플레이트에 종이를 포개어 실측 중심·축과 기준점을 맞추고, 1u/1.5u 키캡·34mm 공·실제 홀더 또는 외곽 모형을 놓아 손가락 접근과 G/H 간격을 확인한다. **공개 인쇄물의 직사각형은 실제 탭·코너 윤곽이 아니므로 외곽을 포개 맞추는 템플릿으로 쓰지 않는다.** 종이 검증은 높이·강성·렌즈 간격 검증을 대신하지 않는다.
7. 기구 더미 조립에서 키 최대 스트로크, 볼 누름/가로 힘, 플레이트 휨, 케이스 조립/분해 경로를 확인한 뒤에 PCB/플레이트 발주 데이터를 만든다.

### 산출물 확인과 재생성

- JSON 파싱, SVG/XML 파싱, HTML 파서 smoke check, Python 구문, 문서 내 로컬 링크 확인 완료.
- Chromium으로 실제 PNG 렌더를 확인했다. 출력 PDF는 한 페이지 A3 가로이며, 벡터 변환까지 계산한 100mm 기준선 길이는 **99.998mm**다([print-validation.json](print-validation.json)). 프린터 배율은 별도이므로 종이에서도 실측한다.
- 기본 좌표/도면 재생성: `uv run design/preliminary/build_artifacts.py`. 표준 라이브러리만 사용한다. 이후 `uv run scripts/render.py`로 PNG/PDF를 갱신하고 `uv run scripts/validate.py`로 검사한다. 기준안과 62키 옵션의 인쇄 HTML은 각각 A3 실제 크기 PDF로 렌더한다.
- 핵심 조립 문구와 Gerber 치수는 원본으로 재확인했다. 저장소 이관 후 재현·검증 절차는 [reproduction.md](../../docs/reproduction.md)에 기록한다.

이번 단계에서 구매, 케이스 가공, PCB 제조 파일 생성, 펌웨어 빌드·업로드는 하지 않았다.
